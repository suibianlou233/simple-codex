# 对话归档与删除

- 对话行的“⋯”菜单提供归档、删除；“已归档”切换到归档列表，支持恢复。
- 归档仅改变 Simple 的列表分类，事件保存在本地数据库；保留完整历史。
- 删除前确认。存在原生 Thread 时先请求固定内核的 `thread/delete`，成功后在
  SQLite 事务中清理 Simple 的任务、事件、Journal、绑定和历史位置关联。
  不直接操作内核数据库或递归删除文件，也不会改动项目文件。
- 内核删除关联的 spawned 子对话；独立项目、其他普通对话保持不变。
- 内核删除失败时保留本地记录。固定版本内核对重复删除返回的精确
  `no rollout found for thread id ...` 错误视为已删除，支持本地提交失败后的重试。
- 有运行中轮次、准备过程或项目执行租约时禁止管理操作；删除期间禁止新模型轮次启动。
- 删除不是磁盘安全擦除；诊断日志、用户此前导出的文件、备份以及项目共享记忆不会自动清除。

参考用户本地 Codex 源码的 `app-server/src/request_processors/thread_delete.rs`。
固定分发内核接口另通过 `scripts/test-kernel-delete.mjs` 在独立临时目录实测，
包含创建、注入测试历史、删除、删除后读取及重复删除，不调用远程模型。

## 调试构建的删除耗时

首次删除会启动内核，而启动前需要校验约 375 MB 的版本包。
开发配置为 `sha2` 单独启用优化，不跳过或缓存校验结果。
同机隔离测量：版本包加载 7415 → 442 ms，内核启动 8617 → 910 ms，
原生删除 51 → 52 ms。该数据不是所有机器或大历史库的耗时保证。
可使用 `kernel_delete_latency` 的显式忽略测试复测；日志新增
`delete_kernel_ready`、`delete_native_completed`、`delete_completed` 分段耗时。
