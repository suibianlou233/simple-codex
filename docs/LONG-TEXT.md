# 长文本输入

消息提交与任务目标不再设置原有的 16,000 字符上限；空消息仍然拒绝。
这不等于模型有无限上下文。实际请求仍受所选模型上下文、网关请求体限制
（当前默认 48 MiB）、内核运输与机器资源约束。不要为了发送长文虚报模型窗口。

粘贴超过 1,000 个 Unicode 字符时，生成独立文本卡片，输入框始终可继续打字。
点击卡片可查看、复制和编辑全文，关闭按钮仅移除对应文本块。
多次粘贴生成多个卡片；为保留准确顺序，光标前的文字随本次粘贴收入卡片，
选区后的文字继续留在输入框。发送时按顺序合并文本块和输入框内容。
发送使用草稿完整原文，不生成磁盘文件、不提交展示占位符。沿用原有首尾空白整理。
手动连续输入不强制折叠。草稿仍使用原有按项目/任务管理的内存状态。

发送后，粘贴正文显示为标题卡片，补充指令保持原有气泡样式。点击卡片在可调整宽度的
右侧阅读栏中查看、选择或复制完整正文。不会改写发送给模型的消息。
分段位置以消息 SHA-256 为键保存到本地界面存储，只存偏移量，不重复存储正文。
重新打开仍可恢复分段；旧消息或无分段数据的长消息整体折叠，避免猜测正文边界。

`LARGE_PASTE_CHAR_THRESHOLD`、`handle_paste`、`pending_pastes` 和
`expand_pending_pastes`。上游 TUI 按粘贴片段建立占位元素，提交时展开；
Simple 使用独立文本卡片和始终可编辑的 textarea，避免可被误编辑的文字占位符。
这份参考源码版本与 Simple 固定分发内核版本不同，本次不修改或升级内核。

编辑/发送/移除，以及后端空白校验和超过旧阈值的输入。
