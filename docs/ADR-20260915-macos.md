# macOS adaptation preview

Status: implementation preview; native compilation and runtime acceptance are separate gates.

## Decision

Support macOS 14+ on Apple Silicon and Intel with separate native packages. The
desktop and kernel architectures must match. Keep the pinned upstream revision
`28327355b861ab6cc76b01c7248663eb1be440cf` and existing candidate protocol adapter.
Build upstream unmodified on Mac; do not apply the Windows V8 sandbox patch.
`build-macos-kernel.py` refuses a dirty or differently pinned upstream checkout,
records actual binary hashes and preserves upstream LICENSE/NOTICE.

The Mac browser uses a WKWebView child in the existing resizable right sidebar.
Its per-project persistent website data store is distinct from the main webview.
Native evaluation accepts only Simple's fixed action script and returns through
Tauri's native callback; it exposes no remote-page desktop IPC or debug listener.
Origin grants, redirect constraints, download/new-window denial and cancellation
remain shared with Windows. Screenshot requests fail explicitly on Mac: no screen
capture permission or whole-window screenshot fallback is introduced.

The existing portable-pty Unix backend already starts the user's default login
shell. Keep its user credential environment filtering and the right sidebar UI.
Mac uses Command+C/V for terminal clipboard; Control+C remains a shell interrupt.
Managed native kernels run in a Unix process group for termination of child processes;
this is lifecycle cleanup, not a sandbox. Keyring's default Apple backend uses Keychain; local database/skill paths use Tauri
platform directories. No Windows sandbox helper is bundled on Mac. Do not claim
Mac sandbox enforcement until native kernel tests demonstrate it. The project-full-access
mode remains unavailable on Mac; use the normal approval mode. Never silently switch
to whole-computer access to work around this limitation.

## Build and verification

GitHub Actions checks both native architectures. A separate opt-in packaging job
builds the fixed kernel then an unsigned app/DMG. It uploads test artifacts only;
it does not publish releases, sign/notarize, or alter the Windows release.

On a Mac with Xcode command line tools, Rustup, Python 3, Node 22 and pnpm:

```sh
python3 scripts/build-macos-kernel.py
pnpm --dir apps/desktop install --frozen-lockfile
cargo fetch --locked --target "$(rustc -vV | awk '/^host:/ {print $2}')"
node scripts/collect-release-licenses.mjs upstream-codex
cd apps/desktop
pnpm tauri build --features bundled-official-kernel -- --locked
```

The platform config is selected automatically by Tauri. For development, set
`SIMPLE_CODEX_KERNEL_MANIFEST` to the absolute path of the generated Mac manifest
before `pnpm tauri dev`. Close an existing Simple instance before using its data.

Native acceptance still needs: startup from Finder, Keychain save/restart,
image drop/paste and provider conversion, PTY input/resize/exit, browser read/fill/
navigation and project-store isolation, denied remote IPC, task stop/recovery,
file/network sandbox enforcement, and signature/notarization before public release.

## V8 packaging correction (2026-09-15)

Run 34983113804 failed when the ARM kernel requested a non-existent sandboxed
V8 archive from denoland/rusty_v8. The pinned Codex revision explicitly selects
its own release artifacts through .github/actions/setup-rusty-v8/action.yml.
The Simple build script now downloads both the sandbox archive and matching
bindings from that release before compiling. scripts/macos-v8-artifacts.json
records the exact hashes from the upstream per-target checksum manifests for
V8 150.4.0, verified by downloading both native pairs. A changed asset or upstream
lockfile version fails closed. No source patch or V8 feature downgrade is used.

The two JIT-bearing helpers are ad-hoc signed using their entitlement files from
the pinned upstream checkout, verified with codesign, then checked with --version
or --help before package hashes are frozen. These checks do not claim notarization
or a complete runtime/sandbox acceptance. The package includes V8_ARTIFACTS.json
so the additional binary dependency can be audited.
